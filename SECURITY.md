# Security Policy

## Supported versions

This project is a single self-hosted application with no release branches.
Only the latest commit on `main` is supported — fixes land there.

## Reporting a vulnerability

Please report security issues privately rather than opening a public issue.

Use GitHub's [private vulnerability reporting][advisory] on this repository, or
email **jzxttzdq@gmail.com**.

[advisory]: https://github.com/Jinzhengxu/poker-table/security/advisories/new

Useful things to include: what an attacker can do, the steps to reproduce it,
and the commit you tested against. You will get an acknowledgement within a few
days. This is a hobby project maintained in spare time, so please be patient
with fix timelines — but anything that leaks cards or lets a player take chips
they did not win will be treated as urgent.

## What counts as a vulnerability here

The threat model is *players at the table*, not anonymous internet traffic. The
interesting bugs are ones where a seated player can gain an advantage:

- **Hole card disclosure.** Any path where a client receives cards belonging to
  another player outside of a legitimate showdown. `Room#buildStateFor` is
  responsible for redaction; a bypass of it is the most serious bug class in
  this codebase.
- **Chip creation or theft.** A sequence of actions that breaks chip
  conservation, misallocates a side pot, or lets a player act with chips they
  do not have.
- **Acting out of turn**, forcing another player's action, or otherwise driving
  the state machine from a seat that should not be able to.
- **Denial of service** against the table — crashing the process, wedging the
  hand state machine, or exhausting memory from a single connection.
- **Injection** through nickname or chat text that executes in another player's
  browser.

## What is out of scope

These are known and documented design choices, not vulnerabilities:

- **There is no authentication.** Anyone who knows the URL can take a seat. The
  URL is the only access control; put it behind your own auth if you need more.
- **State is held in memory.** Restarting the process clears the table and
  resets every stack. There is no persistence to attack.
- **Chips have no value.** There is no wagering, settlement, or payment
  anywhere in this project, so there is nothing financial to steal.
- **A seat token identifies a player.** Anyone holding another player's
  `localStorage` token can resume their seat. That is how reconnection works.
- Reports generated by automated scanners with no demonstrated impact.
